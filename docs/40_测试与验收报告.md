# 40 · 测试与验收报告

> 本文档记录青禾智灌智慧灌溉管理平台的**测试组织方式、用例统计、端到端验收记录、缺陷修复合账与遗留风险**。
> 数据基准：界面改版后（提交 `16dfdb3` 之后）、`708 passed` 的全量测试基线（2026-10-18）。
> 复现命令：`python -m pytest tests -q`、`npm run test:js`。按 `AGENTS.md`，交付前两条命令必须全绿。

## 一、测试策略

系统按「算法与规则」「HTTP 接口」「集成旁路」「前端纯函数」「部署脚本」五个层次组织测试，
目的不是堆用例数，而是把**曾经真实出过的 bug**固化成回归断言。

| 层次 | 手段 | 目的 |
| --- | --- | --- |
| 算法单测 | 直接 import `qinghe.irrigation` 等纯函数，用后端实测锚点断言 | RORI、动态阈值、节水减碳这类数值逻辑一旦漂移，肉眼极难发现 |
| 接口测试 | Flask `test_client` + 临时 SQLite（`FARM_DB_PATH` 指向 tmp） | 状态码、响应体形状、鉴权、用户隔离、入参校验 |
| 集成测试 | 伪造 MQTT 报文调用 `iot.handle_mqtt_message`，monkeypatch `send_property_command` | 遥测 → 落库 → 旁路（心跳/上下文/泵时长/自动调控/告警）全链路 |
| 前端纯函数 | `node --test` 加载 `.mjs` 用例，不依赖浏览器 | 把 `computeRori`、动态阈值等与后端**逐位对齐**固化 |
| 静态检查 | 部署脚本参数解析、模板/JS 引用路径、编码检查 | 部署脚本不能靠人肉试 |

**关键约定**：测试**绝不**真连 MQTT Broker、天气 API、AI API 或钉钉 webhook——全部 monkeypatch 或本地降级分支；
每个测试用独立临时数据库，避免用例间互相污染。

### 4.1 安全复验（未设 `FARM_SECRET_KEY` 的真实进程）

| 攻击手法 | 修复前 | 修复后 |
| --- | --- | --- |
| 用旧硬编码常量自签 token 调 `/api/app_send_command` | 200 + 真实下发指令 | **401** `Token无效或过期` |
| `register` / `login` 传 `int`/`list`/`dict`/`bool` | 500 | **400** |

| 配置 `iot_port='abc'` 后保存 | 后台线程 `ValueError` 崩溃 | 回退默认端口 + warning，不崩 |

### 6.3 系统体检发现的缺陷（P0/P1，本轮已修复）

由独立体检子代理以「只读探测 + 临时库 + 真实进程」方式复现（报告见 [`docs/_healthcheck_report.md`](_healthcheck_report.md)），
修复后每项都有独立回归用例（`tests/test_security.py`，共 105 例）。

| 编号 | 严重度 | 问题 | 攻击/触发方式 | 修复 |
| --- | --- | --- | --- | --- |
| S-01 | **P0** | JWT 鉴权可完全绕过：未配 `FARM_SECRET_KEY` 时密钥回落到源码硬编码常量 `smart_irrigation_secret_2026` | 用该常量自签 token 冒充任意 `user_id` 调 `/api/app_send_command`，实测 200 success 并真实下发设备指令 | 删除硬编码常量的签名用途；未配置时用 `secrets.token_urlsafe(48)` 生成进程级随机密钥（重启变化），常量降级为「是否已配置」哨兵 |
| S-02 | **P0** | 非字符串 JSON 字段直接 500：`(data.get('username') or '').strip()` 只兜 falsy 不校验类型 | `username: 12345` / `list` / `dict` / `bool` → `AttributeError` → 500（13 个类型混淆用例 11 个命中） | 新增 `qinghe/validators.py`（`as_str`/`as_stripped`/`as_int`/`as_bool`/`truncated` + `ValidationError(400)`），register/login/app_login/change_password/notify_alert 全走校验 |
| S-03 | P1 | 登录限流被单个请求头绕过：限流键取 `X-Forwarded-For` 且不验证来源 | 轮换 XFF 后连续 12 次失败全 401，无 429，可无限爆破 | 默认用 `remote_addr`；仅 `FARM_TRUST_PROXY=1`（精确匹配）才取 XFF 第一跳 |
| S-04 | P1 | 脏 `iot_port` 使 `connect_huawei_iot` 抛 `ValueError` 崩后台线程 | 配置写入非法端口后保存配置 | `_safe_iot_port()` 兜底回退 `IOT_PORT_DEFAULT` 并记 warning |
| S-05 | P1 | `notify_alert` 的 `msg`/`level` 类型混淆 500 | 传非字符串字段 | 随 S-02 的 `validators` 修复 |

**同时修掉的隐性问题**：`change_password` 的「原密码错误」「新密码过短」两个分支原先**隐式返回 200**，已补为 400。

**体检实测排除（旧代码有、重构后已修）**：SQLite `database is locked`（WAL + `busy_timeout`）、连接泄漏（全仓仅 1 处 `connect`、48 处 `closing` 包裹）、`mqtt_clients` 竞态（RLock 全覆盖）、前端 XSS（`innerHTML` 实际赋值 0 处）、`setInterval` 泛滥（合并为统一 tick）、`localStorage` 全表读写、`FARM_DEBUG` 默认 0、CSP 与 CDN 一致。

### 6.4 遗留与已知限制（不修，写入文档）

| 项 | 说明 |
| --- | --- |
| ESP32 边缘端自治固件 | 说明书设计的 `Eh ≤ −100 mV` / `DO ≤ 1.5 mg/L` 强控红线**未在固件实现**，仅服务端 + 文档约束；断网时失去保底强控 |
| 微信小程序 | 仅预留 `/api/app_login`、`/api/app_send_command` 两个 JWT 接口，**无小程序端代码**，材料中须标注「待实现」 |
| 多进程部署 | 运行态（遥测缓存、自动调控节流、日志队列）存进程内存，仅支持 waitress **单进程多线程**，不可横向扩进程 |
| AI 上下文 | 已注入 RORI/遥测/6 日降雨上下文，但未做 CoT 可解释输出的强约束 |
| 钉钉推送 | webhook 有 2 次退避重试，失败仅记日志，无持久化重试队列 |
