### 1.3 第 1 章 研究背景 — 要点

- **研究意义**：水稻灌溉用水量占农业总用水量比例极高；传统淹灌使稻田土壤长期处于**强还原状态**，**Eh 显著降低**，导致**厌氧产甲烷菌**大量繁殖，产生并排放大量**甲烷(CH₄)**。
- **技术路线**：加气灌溉通过向灌溉水中混掺空气或**微纳米增氧**，提升土壤根区 DO 与 Eh，破坏产甲烷菌厌氧生存环境，从源头减少温室气体排放。
- **1.2.2 研究现状**：农田灌溉正由人工巡查向数据驱动转变；**基于边缘网关配接传感器 + MQTT 协议对接云平台**的控制方案已进入大田示范阶段；调度算法方面**引入中短期气象数据实行基于降雨预测的前馈控制**已成趋势。**空白点**：现有气象前馈调度多局限于**旱作物的干旱预警与防涝排水**，将中短期气象要素同时引入**稻田控水蓄雨与根区气体环境调控**的交叉复合研究仍较少见。
- **1.3 局限性（两条）**：
  1. **控制逻辑呈现被动局域后馈性** — 依赖本地单片机**固定阈值触发**，须在土壤水分跌破下限或氧环境恶化后被动开启；缺乏趋势预判、存在时滞、边缘端无法处理中短期气象预测数据。
  2. **缺乏与中短期气象要素的前馈联动机制** — 南方稻区降雨时空分布极不均匀；传统装置在土壤水分低于下限时**立即触发抽水灌溉**，常出现"刚灌满水、随后突降暴雨"，多余水被迫开闸作**无效排水**排掉，浪费灌溉水与电能，天然降雨利用率低；暴雨后长时间深淹使根区氧环境剧烈恶化，**极易引发阶段性碳排放洪峰**。
- **1.3（本作品研究内容与切入点）**：利用 **FireBeetle ESP32-E 边缘网关**对接 **Easy IoT 物联网平台**，创新引入**和风天气 API 的未来 6 天中短期滚动降雨预报数据**；动态量化水位、水分、DO、Eh 等多维异构指标，运行 **RORI 融合方程**；控制层执行结合中短期降雨预测的控水调度，提前预留田间蓄水空间留存降雨，并在恶劣天气前主动防御性加气；决策层引入 **DeepSeek 推理大模型**构建**农作自主体(AI Agent)**。

### 1.4 第 2 章 设计思路 — 要点

- **2.1 引入 6 天天气前馈，实现跨周期降雨调蓄**：将**和风天气 API 未来 6 天滚动降雨预报**作为**前馈干预算子**引入算法内核；结合中短期天气走势与**田间水量平衡原理**演算。**若预测有强降雨信号前馈 → 主动下调灌溉触发含水率下限**以拦截人工补灌计划，提前预留田间调蓄库容；**雨后自适应放宽蓄水高度上限**，最大化提升天然降雨利用率并削减抽水能耗。
- **2.2 多维特征协同互补，构建根区缺氧风险度量体系**：设计 **RORI 复合度量指标**；将反映根区厌氧状态的 **DO、Eh 电化学指标**与**渠道水位、土壤水分表观物理特征**有机结合；通过**特征归一化方程**将各量纲物理量转化为**无量纲子风险因子**，再通过**复合加权增益方程**动态解算，为**气泵和排涝泵的分级精准调控**提供量化依据。
- **2.3 基于 DeepSeek 认知推理内核的人机协同自适应决策链**：云端部署 DeepSeek 大模型认知推理内核；将渠道水位、土壤湿度、DO、Eh 多维高频特征流与气象前馈算子进行**特征空间对齐**；利用**序贯因果推理与启发式策略演算**推演农田水量演变态势与多变量耦合扰动；在 **Web 端和小程序主页**实时生成具备**演化机理解释性的主动控制预案**，通过**人机协同接口(Human-in-the-Loop)**向管理人员发起调度建议；经**终审确认**后云端方下发机电执行指令。实现控制逻辑的透明化与可追溯性。
- **四阶段解构**："多源感知、风险预测、智能决策、自动调控"，**高阶算法集中于 Web 端运行以精简现场网关算力开销**。
- **双向防御机制**：
  1. **边缘端本地自治保护** — 硬件网关在本地对现场 Eh 与 DO 指标**不间断轮询**；一旦网络中断且**核心减排专利指标超限**，绕过网络层延迟直接在本地强控开启气泵加气增氧。
  2. **网页端双向切换** — 支持**全自动托管与人工远程控制无缝切换**。

### 1.5 第 3 章 设计原理与核心算法（★ 后续设计文档核心依据）

#### 3.1 异构感知数据无量纲化处理

采集现场环境要素：**DO、Eh、渠道水位、土壤湿度**。采用**分段定界归一化方法**映射为区间内无量纲子风险特征因子。

**3.1.1 氧化还原电位风险因子 S_Eh**

- 参数：最适有氧上限 **Eh_max = 300 mV**；极限厌氧下限 **Eh_min = −150 mV**
- 公式：

$$S_{Eh} = \max\big(0.0,\ \min\big(1.0,\ \frac{Eh_{max} - Eh_{real}}{Eh_{max} - Eh_{min}}\big)\big) = \frac{300 - Eh_{real}}{450}$$

**3.1.2 根区溶解氧风险因子 S_DO**

- 参数：正常氧分压上限 **DO_max = 8.0 mg/L**；极限缺氧下限 **DO_min = 0.0 mg/L**
- 公式：

$$S_{DO} = \max\big(0.0,\ \min\big(1.0,\ \frac{DO_{max} - DO_{real}}{DO_{max} - DO_{min}}\big)\big) = \frac{8.0 - DO_{real}}{8.0}$$

**3.1.3 地表排涝与土壤水分风险子项**

- 标定说明：**土壤湿度传感器的模拟量输出值随土壤湿润程度升高而降低** → 原始模拟量数值越低表示土壤越湿润、根区通气条件越差、缺氧风险越高。
- 引用：已有加气控制灌溉减排装置采用 **FDR 土壤湿度传感器**监测土壤含水率，依据水稻不同生育期含水率上下限进行灌水与加气控制 [11]。
- 公式（Water_A0 = 渠道水位模拟量，Soil_A2 = 土壤湿度模拟量）：

$$\text{Risk}_{water} = \begin{cases} \dfrac{Water_{A0} - 5}{100}, & Water_{A0} > 5 \\ 0, & Water_{A0} \le 5 \end{cases}$$

$$\text{Risk}_{soil} = \begin{cases} \dfrac{2000 - Soil_{A2}}{2000}, & 0 < Soil_{A2} < 2000 \\ 0, & \text{其他} \end{cases}$$

#### 3.2 RORI 多维融合原理

$$RORI = \lfloor P_{risk} \times 100 \rfloor$$

$$P_{risk} = \min\big(1.0,\ \omega_1 \cdot S_{Eh} + \omega_2 \cdot S_{DO} + \omega_3 \cdot \max(Risk_{water},\ Risk_{soil}) + \gamma \cdot Risk_{water} \times Risk_{soil}\big)$$

**权重系数（原文赋值）**：

| 符号 | 含义 | 取值 |
|---|---|---|
| ω₁ | 氧化还原电位风险子项解算权重系数 | **0.35** |
| ω₂ | 根区溶解氧风险子项解算权重系数 | **0.35** |
| ω₃ | 水土环境状态风险子项解算权重系数 | **0.30** |
| γ | 水土交互风险耦合增益系数 | **0.5** |

**表 3-1　根区缺氧风险指数(RORI)分级预警**

| 风险级别 | RORI 数值范围 | 大屏渲染与预警状态 | 执行机构(泵阀)联动控制策略 |
|---|---|---|---|
| Ⅰ级（重度风险） | **RORI ≥ 70** | 红色高危预警；蜂鸣器激活 | 网页端发布**满载控制字**，驱动微气泡加气机**全满载开启**，强制根区增氧减排；同时密切监控渠道水位 |
| Ⅱ级（中度风险） | **40 ≤ RORI < 70** | 橙色中危预警；状态指示闪烁 | 网页端发布**间歇控制字**，驱动微气泡加气机进行**周期性脉冲加气**，动态补充根区损耗氧量 |
| Ⅲ级（安全状态） | **RORI < 40** | 绿色安全渲染；运行状态正常 | 判定根区有氧环境优良。微气泡加气机处于**低能耗休眠待机**状态，现场网关维持常态化异构数据不间断轮询与发布 |

#### 3.3 未来 6 天降雨预测前馈与动态阈值修正算法

**(0) 6 日滚动总预测降雨量**

$$P_{6d} = \sum_{t=1}^{6} \omega_t \cdot P_t$$

- P_t：未来第 t 天的预测降雨量 (mm)
- ω_t：**时间跨度衰减算子**，用于平抑远期气象预报的不确定性
- **衰减系数序列（第 1→6 天）**：`[1.0, 0.9, 0.7, 0.5, 0.4, 0.3]`

**(1) 动态降雨有效利用系数 α 分段定界**

$$\alpha = \begin{cases} 0.95, & P_{6d} \le 10\ \text{mm} \\ 0.75, & 10\ \text{mm} < P_{6d} \le 50\ \text{mm} \\ 0.45, & P_{6d} > 50\ \text{mm} \end{cases}$$

**(2) 动态执行下限 Limit_lower（前馈控水等雨）**

当预测到中短期内有雨 (**P_6d > 0**) 时，自动调低触发人工补灌的体积含水率边界，阻断常规灌溉计划：

$$Limit_{lower} = \max\Big(45\%,\ Limit_{min} - \frac{\alpha \cdot P_{6d}}{H_{root}} \times 100\%\Big)$$

- **Limit_min**：当前生育期的基础体积含水率下限
- **H_root = 200 mm**：核心活动根系层厚度
- **45%**：为避免水稻极端受旱的**防枯萎保底安全线**

**(3) 动态执行上限 Limit_upper（蓄雨型控灌）**

- 常规状态下人工灌溉控制上限为 **Limit_max**
- 当系统判断有中短期强降雨信号前馈（**P_6d ≥ 15 mm**）时，上限自适应放宽扩展至**最大允许安全蓄水深 Limit_hp**，充分利用稻田自身调蓄空间留存雨水

#### 3.4 基于 DeepSeek 内核的边云协同认知决策模型

**三层嵌套防御链**（级联 "特征解析、云端认知、就地否决"）的 Human-in-the-Loop 控制闭环：

| 层级 | 名称 | 物理职责 |
|---|---|---|
| 第一层 | **解析特征层** | 高频解析 3.1~3.3 节数理方程，将物理低阶信号转化为具农学物理意义的**专家特征矢量 (Feature Vectors)** |
| 第二层 | **认知决策层**（云端 DeepSeek 内核） | 特征矢量动态馈入决策空间，依托大模型内核开展**序贯因果推理与多变量长周期策略博弈**，输出兼顾"低碳与节水"的全局最优调度方案 |
| 第三层 | **就地保底层** | 底层网关**就地硬编码核心减排专利的绝对红线（Eh ≤ −100 mV 或 DO ≤ 1.5 mg/L）**，拥有**最高强控制否决权**，就地阻断大模型可能的"幻觉"风险或断网故障 |

### 2.2 一、软件概述

#### 1.1 软件简介 — 要点

- 面向**农田灌溉与低碳水利调控**场景的管理软件。
- 构建**多源感知、风险预测、智能决策、自动调控四阶段闭环协同调控机制**。
- **平台三部分组成**：
  1. **网页监控中心** — 供管理人员登录查看农田状态、分析变化趋势、设定调控参数、手动干预设备，是操作人员与系统交互的主要入口
  2. **后端服务** — 运行于服务器，通过 MQTT 与华为云保持连接；实时订阅并接收田间设备上报数据，转发至网页端并留存历史记录；接收控制指令下发至田间设备
  3. **田间采集控制终端** — 外接**渠道水位传感器、土壤湿度传感器、根区溶解氧传感器、氧化还原电位传感器以及水泵、气泵驱动电路**，周期性采集田间多维数据，通过 **MQTT 协议上传至华为云 IoTDA 设备接入平台**
- 引入**和风天气平台未来 6 天降雨量预测**作为前馈信息。
- 依据 **RORI** 自动调节气泵增氧，实现**节水灌溉、根区增氧与固碳减排的协同**。

```javascript
function computeRori(waterAdc, soilAdc) {
  var W_EH = 0.35, W_DO = 0.35, W_WATER_SOIL = 0.30, GAMMA = 0.5;
  var waterMm = Math.max(0, Math.min(waterAdc / 4095 * 300, 300));
  var soilPct = Math.max(0, Math.min((4095 - soilAdc) / 4095 * 100, 100));
  var sEh = Math.max(0, Math.min((300 - ehValue) / 450, 1.0));
  var sDo = Math.max(0, Math.min((8.0 - doValue) / 8.0, 1.0));
  var riskWater = waterMm > 5 ? Math.max(0, Math.min((waterMm - 5) / 100, 1.0)) : 0;
  var riskSoil = Math.max(0, Math.min(soilPct / 100, 1.0));
  var pRisk = W_EH * sEh + W_DO * sDo
            + W_WATER_SOIL * Math.max(riskWater, riskSoil)
            + GAMMA * riskWater * riskSoil;
  return Math.max(0, Math.min(pRisk, 1.0)) * 100;
}
```

```javascript
var H_ROOT = 200;
function computeDynamicThreshold() {
  var fc = window.forecastData || [];
  var P6d = 0;
  for (var i = 0; i < fc.length && i < RAIN_WEIGHTS.length; i++) {
    P6d += RAIN_WEIGHTS[i] * (parseFloat(fc[i].precip) || 0);
  }
  var alpha = P6d <= 10 ? 0.95 : (P6d <= 50 ? 0.75 : 0.45);

  var humiUp   = parseInt(document.getElementById('humiUpInput').value) || 80;
  var effLower = Math.max(45, humiDown - (alpha * P6d / H_ROOT) * 100);
  var effUpper = (P6d >= 15) ? Math.min(100, humiUp + 15) : humiUp;
  return { P6d, alpha, effLower, effUpper, baseLower: humiDown, baseUpper: humiUp,
```

### 5.4 水泵/气泵驱动逻辑

```c
#define PUMP_ON_A  HIGH   // 开泵时 D7 电平
#define PUMP_ON_B  LOW    // 开泵时 D9 电平
#define PUMP_OFF_A LOW    // 关泵时 D7 电平
#define PUMP_OFF_B LOW    // 关泵时 D9 电平

#define AIR_PWM_CH    0      // LEDC 通道
#define AIR_PWM_FREQ  5000   // 5 kHz
#define AIR_PWM_RES   8      // 8 位分辨率（0~255）
```

- `setWaterPump(bool on)`：按上述宏设置 D7/D9 电平；状态字符串 `"on"` / `"off"`（匹配华为云物模型 string 类型）
- `setAirPump(int level)`：`constrain(level, 0, 255)` + `ledcWrite(AIR_PWM_CH, level)`；`level > 0` → `"on"`，否则 `"off"`；**网页端 `on` 即 255（满档）**

### 5.5 传感器量程与标定

| 传感器 | 引脚 | 量程换算 | 代码 |
|---|---|---|---|
| **DO 溶解氧** | A4 | 模拟输出 **0~3.3V 对应 0~20.0 mg/L** | `doMgl = (adc / 4095.0) * 20.0`，限幅 `0.0 – 20.0` |
| **Eh 氧化还原电位** | A6 | 模拟输出 **0~3.3V 对应 −150 ~ 300 mV**（说明书 3.1.1 设定范围） | `ehMv = -150.0 + (adc / 4095.0) * 450.0`，限幅 `−150.0 – 300.0` |
| **水位** | A0 | 原始 ADC 直传（网页端换算 `adc/4095*300` → 0–300 mm） | `analogRead(WATER_SENSOR_PIN)` |
| **土壤湿度** | A2 | 原始 ADC 直传（网页端换算 `(4095-adc)/4095*100` → 0–100%） | `analogRead(SOIL_SENSOR_PIN)` |

常量：`DO_ADC_MAX = 4095.0`、`DO_FS_MGL = 20.0`、`EH_ADC_MAX = 4095.0`、`EH_MIN_MV = -150.0`、`EH_MAX_MV = 300.0`。注释明确："**按实际探头标定曲线调整**"。

### 5.6 上报报文格式

**物模型上报（每 3 秒）**：

```json
{"services":[{"service_id":"esp","properties":{
  "waterlevel":<int>,"humidity":<int>,
  "do":<float,1位>,"eh":<float,0位>,
  "water_pump":"on|off","air_pump":"on|off"}}]}
```

**M2M 自定义 Topic 报文（`/esp32e/source`）**：

```json
{"waterlevel":<int>,"humidity":<int>,"do":<float,1位>,"eh":<float,0位>,
 "water_pump":"on|off","air_pump":"on|off"}
```

**指令执行后立即调 `publishPumpStatus()`**，让泵状态即时到达网页端（不必等 3 秒周期）。

### 5.7 指令解析（`callback`）

1. **物模型属性设置路径**：`topic` 含 `sys/properties/set` → `propValue(msg,"air_pump")` / `propValue(msg,"water_pump")` 取值；有值则执行；再从 topic 提取 `request_id=` 后段，发布应答到 `TOPIC_PROP_SET_RESP_PREFIX + <request_id>`
2. **兼容路径**：查找 `"device"` 与 `"action"` 键，`trimValue()` 裁剪冒号/空格/引号，截断到 `"`、`,`、`}`、`]`；支持 `water_pump`/`SB` 与 `air_pump`/`QB` 两种别名

### 5.8 控制字对照（前端识别）

| 控制字 | 含义 |
|---|---|
| `QB_ON` | 气泵开 |
| `QB_OFF` | 气泵关 |
| `SB_ON` | 水泵开 |
| `SB_OFF` | 水泵关 |

### 5.9 已知硬编码问题（供后续设计文档注意）

- `SSID` / `PASSWORD` / `MQTT_PASS` / `MQTT_SERVER` / `DEVICE_ID` **全部硬编码在固件源码中**，与 `AGENTS.md`"密钥、设备口令、API Key 不得硬编码进源码"的约定冲突
